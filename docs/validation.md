# Проверка 2026-09-14

Проверено на Godot 4.7.2 stable, macOS, Apple M4 Max. Рендер Forward+ / Metal.

- Импорт проекта и компиляция GDScript/шейдеров в целевой папке: без ошибок.
- `simulation_test.gd`: 259 проверок, 0 ошибок. Правила урона, способности, отмена готовности, JSON-снимки, помощь союзнику, щит, дебафф, 108 сочетаний волна/игроки/сложность, три босса, бонусы, победа/поражение, серии фиксированных симуляций.
- `input_test.gd`: клавиатурное подтверждение и отмена, управление только своим игроком, помощь и выход из помощи, выбор бонуса и переход к следующей волне — без ошибок.
- `npm test`: оба сценария сервера комнат проходят; распределение четырёх мест между ТВ и телефоном, запрет чужих фишек, вместимость, старт только ведущим, передача снимков только ведущим, разрыв соединения и уплотнение мест после ухода из лобби.
- `godot-integration.mjs`: два настоящих процесса Godot. Ведущий получает команду второго игрока; второй получает 15 снимков и наблюдает общий бросок. Оба завершаются успешно.
- Отдельная проверка браузерного контроллера через UI: вход в комнату настоящего headless Godot, место P2, выбор щита, готовность. Godot подтверждает получение обеих команд.
- Проверены живые кадры главного меню, арены, броска со следами/куполом, босса и карточек улучшений.
- Исправлено предупреждение о незавершённых AudioStreamPlayback при закрытии. После явной остановки голоса и завершения аудиокадра игра и тест управления закрываются без этого предупреждения.
- Проверены синтаксис JavaScript и shell-лаунчера, а также отсутствие ошибок whitespace в текстовых изменениях.

Не проверены: реальные физические геймпады, самостоятельные Windows/Linux/macOS-экспорты, слабые ПК, Smart TV, международная сеть. Публичный relay ещё не развёрнут. Баланс стартовый и требует живых партий. Автотесты не доказывают соответствие постановочному референсу.

## Проверка управления контроллерами — 2026-09-15

- `node relay/test/controller-integration.mjs`: два экземпляра полного `Main`, два WebSocket-соединения и настоящий локальный relay. Четыре геймпада (два у ведущего, два у гостя) независимо задают направление крестовиной и стиком, включают способность, заряжают бросок, задают подкрутку, подтверждают и отменяют готовность. Результаты проверяются на ведущем и в снимке гостя.
- `node relay/test/controller-integration.mjs res://tests/lobby_network_test.gd`: два местных геймпада и WebSocket-клиент телефона; проверяются направление, сила, подкрутка, способность, готовность и бонус телефона.
- События геймпадов синтетические. Проверка физического оборудования и его системных раскладок остаётся отдельной.

## Постоянные контроллеры телефонов — 2026-09-15

- `phone_hub_test.gd`: два полных экземпляра ТВ автоматически запускают два встроенных HTTP/WebSocket-сервера Godot. Проверены занятый порт, HTTP-страница, подключение телефонов до игры, общий матч двух ТВ, маршрутизация телефона гостя в P4, возврат в меню и следующий локальный матч без переподключения телефона. После закрытия ТВ оба порта освобождаются.
- `phone_connection_test.gd`: адрес для браузера, LAN вместо loopback, внешний домен/TLS, собственный порт, IPv6 внешнего сервера и отсутствие локального адреса.
- `tests/support/test_main.gd` отключает автозапуск серверов и сохранение пользовательских настроек в обычных тестах и постановочных кадрах. Полный запуск проверяет отдельный `phone_hub_test.gd`.
- Автономные платформенные экспорты и физические телефоны в Wi-Fi пока не проверены; интеграция использует настоящие локальные TCP/WebSocket-соединения.

## Встроенный сервер без Node.js

- `native_rooms_test.gd`: подключение телефона без кода, права на фишку, числовые JSON-слоты, нормализация силы/подкрутки, запрет новых мест во время матча, сохранение хаба после выхода телефона.
- `phone_hub_test.gd`: полный сценарий двух ТВ и двух телефонов теперь проходит на встроенном сервере, без запуска внешнего процесса.
- Живой браузер: страница не подключается сама, «Подключить» присоединяет телефон без кода, команда готовности получена Godot (`BROWSER_SHOT_OK`).
- Страница контроллера упаковывается экспорт-плагином; Godot отвечает за WebSocket handshake и кадры. HTTP обслуживает только известные статические маршруты, с ограничениями запросов и частичной отправкой.
