# Файлы проекта и рабочие материалы

## Что хранится в Git

- `assets/` — ресурсы, используемые игрой.
- `design/references/` — утверждённые референсы и описание их происхождения.
- `design/audio/` — заметки о выборе и подготовке музыки.
- `tests/*_capture.gd` — сценарии записи игры. Папки для результатов создаются при запуске.
- `tools/` — повторно используемые инструменты; `tools/aim_energy/` содержит отдельный эксперимент с физикой, а не действующие правила игры.

В `work/` хранится только служебный `.gdignore`: он исключает рабочие материалы из импорта Godot. Остальное содержимое папки игнорируется Git. `design/.gdignore` также исключает художественные референсы из импорта игры.

## Что остаётся локально

Видео AVI/MP4/GIF, серии скриншотов, музыкальные пробы, журналы, ответы сервисов генерации и старые копии исходников находятся в `work/`. Они не нужны для запуска игры и отсутствуют в свежем клоне.

Пути `work/...` в отчётах обозначают локальные результаты проверки. Такие ссылки не предоставляют файлы другим участникам. Для совместного просмотра прикладывайте нужные записи к задаче или храните в отдельном хранилище. Перед удалением локальных оригиналов сохраните материалы, которые нельзя повторно получить, в резервную копию.

Утверждённый референс врагов сохранён в `design/references/enemy-materials-v1.png`. Его оригинальная копия и все остальные рабочие файлы при очистке Git оставлены на диске.

Полезные сценарии из `work/` перенесены в:

- `tests/arrow_charge_capture.gd`;
- `tests/hearth_fire_capture.gd`;
- `tools/aim_energy/`;
- `tools/prepare_menu_previews.py` (исходные AAC нужны локально в `work/kyrgyz-menu-rework/quiet/`).

Одноразовые скрипты замены кода из `work/polish-v3/` и копии `before/` не являются инструментами для текущей версии. Они остаются локально и в прежней истории Git.

## Размер истории Git

Удаление файлов из индекса и `.gitignore` предотвращают их добавление в следующие коммиты, но не удаляют содержимое прежних коммитов. После публикации очистка всей истории требует отдельной согласованной операции: резервной копии, переписывания затронутых веток и тегов, принудительного обновления удалённых ссылок и синхронизации других клонов. Обычный клон с полной историей сохраняет прежний объём; для текущей версии без старой истории можно использовать `git clone --depth 1` после публикации коммита очистки.
